# 下一个版本（草稿）

## Antigravity 每轮少等 6 秒

用 agy 模型说话时，每一轮都要新起一个 `agy` 进程。实测一次最小回合共 8.5 秒，其中模型生成只占 2.2 秒，剩下 6.3 秒全花在进程自己的启动上（登录态、MCP 握手）。

现在这笔开销藏起来了：一轮结束后，顾清影立刻把下一轮要用的 agy 进程拉起来晾着，等你再说话时直接把内容喂进去。agy 在读输入之前就会把启动流程跑完，所以第二轮起基本只剩模型生成的时间。

几处刻意的保守：

- 只有常驻 daemon 会预热。单次 CLI 用完就退，留下的进程会成为孤儿。
- 只晾一个，默认 5 分钟没人用就自动关掉。晾着的是一个 agy 加一条 MCP 桥，不值得为了省几秒一直占着内存。时长可以在设置里改（「Antigravity 中转 → 预热进程保留时长」，对应 `plugins.antigravity.warm_idle_seconds`），设成 0 就完全关掉预热。
- 换会话、换发起来源、换续传目标都不复用。MCP 桥在启动那一刻就把会话身份读死了。
- 晾着的进程要是死了，会自动退回冷启动重来一次。判据是"一行输出都没有过"，这时模型还没被调用，不会多花额度。

第一轮、隔了超过保留时长的那一轮，以及来源变了的那一轮，仍然是冷启动。
