# 07 · 知识库、技能、表情包与脚本

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 顾清影 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `gqy -h`、`gqy config`、仓库 README 及源码为准。

这四样是 顾清影 的“可调教”内容：你不用改代码，就能让它掌握新知识、学会新流程、发新表情、调用新脚本。

## 1. 知识库（kb）

### 它是什么

一个带索引的 Markdown 文件库，放长期参考资料（不是记忆，记忆走 `remember_fact`）。默认知识库来自本仓库的 `kb/` 目录（09-24 起，内容是一份 顾清影 使用手册；此前是上游作者的 Arch 指南），打包在安装前缀的 `share/gqy/default-kb/`（Nix 在 store 里，Linux 另认 `/usr/share/gqy/default-kb/`，`GQY_DEFAULT_KB_DIR` 可覆盖）。

### CLI

```bash
gqy kb add 文件.md
gqy kb add 目录/
gqy kb list
gqy kb search "N卡驱动"
gqy kb find "nvidia"
gqy kb read 文件名 --start 1 --lines 200
gqy kb remove 文件名
gqy kb stats
gqy kb reindex
gqy kb embed reindex --quiet   # 配了 embedding 才有意义
```

也可以直接用自然语言让 AI 操作：`search_knowledge_base`（`by=content` 搜内容 / `by=name` 找文件）检索，`read` 带 `kb:` 前缀读全文，`kb` 用补丁语法（Add/Update/Delete File）增改删。

### 检索与索引

- 默认关键词/短语检索：`search`（内容）和 `find`（文件名），对应工具里的 `by=content` / `by=name`。关键词命中分内容 +90、文件名 +140，再加词项命中/覆盖率和窗口分；语义检索开启且关键词分较弱时才混合语义分。
- 语义检索默认开启（`embedding.enabled` + `plugins.knowledge_base.embedding_enabled`），默认用内置本地模型 `bge-small-zh-v1.5-int8`（需要 ONNX Runtime：预编译包和 Nix 包自带 `lib/gqy/libonnxruntime`，自行编译时要系统里装一份），也可以在 `embedding` 里换成远程 `/embeddings` 接口。`gqy kb embed reindex` 或 `gqy embed reindex` 重建向量索引；写入文件后会自动起子进程补索引。向量按模型打标签，换模型后旧向量作废、增量重建。
- 语义检索只是辅助：运行库缺失、模型目录缺失或远程超时时静默退回关键词，`gqy embed status` 能看到原因。
- 限制：单文件大小、读取行数、snippet 长度、top_k、min_score 等都在插件配置里。
- 用户知识库目录：`~/.gqy/data/kb/`（默认，可改 `plugins.knowledge_base.data_dir`；内部还有 `files/`、`kb_meta.db`、`semantic_index.db`）。

### 默认知识库更新

```bash
gqy update-default-kb
```

- 从本项目仓库（`yxxbc/gqy-agent` 的 `gqy` 分支）部分克隆 + sparse checkout，只取 `kb/**/*.md`，校验后整体替换默认知识库的 `kb/` 前缀；旧的 Shorin Wiki 缓存克隆会顺手删掉。
- 「有更新」比的是 `kb/` 目录的 tree 哈希（GitHub trees API，5 秒超时），不是提交号，所以代码提交不会反复提醒。状态记录在 state 目录；每 24 小时检查一次。
- 安装包里缺默认知识库不报错，只是默认知识库为空（`cargo install` 装的就是这样，可以直接跑 `gqy update-default-kb` 补上）。

## 2. Skills（技能）

Skill 是一份 Markdown 操作手册：模型遇到匹配场景时加载它，按里面的步骤和工具执行。这是给 AI 的“SOP”。

### 内置技能

内置技能编译进二进制，清单是 `src/skills/mod.rs` 的 `BUILTIN_SKILLS`。平台级的任何人格都开着、不能关；可选件默认人格全开，自定义人格要在人格清单里点名。

| 技能 | 文件 | 级别 | 作用 |
|---|---|---|---|
| skill-creator | `src/skills/skill-creator.md` | 平台级 | 教 AI 如何创建一个好 skill |
| script-creator | `src/skills/script-creator.md` | 平台级 | 脚本接口契约（头部、stdin JSON、退出码） |
| gqy-cli | `src/skills/gqy-cli.md` | 平台级 | 她自己的命令行手册，免得猜错子命令 |
| webui-theme | `src/skills/webui-theme.md` | 平台级 | 写 WebUI 主题（只改 CSS token） |
| linux-game-compatibility | `src/skills/personas/default/linux-game-compatibility.md` | 可选 | 组合 ProtonDB/AreWeAntiCheatYet/CanIPlayOnLinux 判断游戏兼容性 |

### CLI

```bash
gqy skills list
gqy skills show 名字
gqy skills enable 名字
gqy skills disable 名字
gqy skills remove 名字
gqy skills stats
gqy skills prune
```

### 创建流程

1. 对 顾清影 说“帮我创建一个解决 XX 问题的技能”。
2. AI 调 `manage_skill(action=create)` 生成**草稿**，放在 `~/.gqy/state/skill-drafts/`。
3. AI 用 `action=update` 完善；`action=list_drafts` 查看草稿。
4. 确认无误后 `action=publish` 发布（`scope=global` 进全局技能目录，`scope=persona` 只给当前人格）。
5. 用 `load_skill` 测试；不需要就 `action=delete`。

### 安全与规则

- 技能默认允许在 AI 按技能操作时执行命令；`skills.allow_command_execution=false` 全局禁止技能命令执行。
- 用户技能属于用户资源，`gqy export/import` 会带上。
- 技能目录：全局 `~/.gqy/extensions/skills/`，人格专属 `~/.gqy/extensions/skills/personas/<人格>/`（私有人格在 `home/<user>/personas/<名>/skills/`）；旧布局没迁完时仍在 `~/.gqy/data/skills/`。
- 技能优先级：当前人格技能 > 全局用户技能 > 内置技能；同名会遮蔽。
- 开关分三种（`src/skills/admin.rs`）：平台级内置技能固定开着；人格自己那一层用目录里的 `.disabled` 标记（与 `gqy skills disable` 同一机制）；全局层和可选内置技能写进当前人格清单的 `plugins.skills` 白名单。WebUI 设置 → 插件 →「扩展」和终端配置器里能看到含已关闭在内的全部技能并逐个开关（接口 `/api/extensions*`）。
- 草稿未发布保留 30 天，已发布归档保留 24 小时。
- SKILL.md 的 frontmatter 必填 `name`/`description`；`name` 必须与目录名一致；`allowed-tools` 只是元数据，不授权限。
- 发布是原子操作（新技能绝不覆盖、更新失败自动回滚），全程拒绝 symlink。

## 3. 表情包（memes）

### 存储位置

- 当前不带内置表情包（09-14 改名时删掉了上游的 Miyu 表情库）；`GQY_MEMES_DIR` 或安装前缀 `share/gqy/memes/` 下放了才会有系统层。
- 用户目录：`~/.gqy/data/memes/`，默认人格的库名是 `gqy`。
- 索引：每个表情库目录一个 `index.json`，包含每条表情的 id、标签、描述、文件等。

### 自动发送

- 聊天时 顾清影 会按概率自主发符合情境的表情；插件配置可调 `auto_send_probability`（默认 0.05）、置信度、冷却、图片尺寸等。
- 自动发送只跟人格库走：表情库要自己攒，把图片路径给 AI 让其 `manage_meme(action=add)`。
- 识图：添加图片时，AI 自动调用多模态模型分析内容并写描述（默认 opencode vision 模型即可，不配也能用）。
- 工具分两个，按**加载成本**分而不是按「像不像一件事」：
  - `use_meme`（`action=search` 找候选 / `show` 发送）——发表情是高频动作，常驻目录，不需要先加载。
  - `manage_meme`（`action=add` / `update` / `delete`）——低频，挂在 `memes` 组里懒加载，平时只占一条 155 字符的精简条目。
- 两个工具在终端和群聊里都有。`manage_meme` 是写工具，但只写人格自己的表情库目录，和 `generate_image` 一样属于平台注册表「全员只读」那条断言的明示例外。
- 识图入库门槛很严：分类置信度必须 100，7 个正向 gate 全过、5 个风险 gate 全不过，才会自动保存。
- QQ 群还有“表情口袋”插件：按概率（默认 2%）自动收集群友图片入表情库；管理员可保存/删除。

## 4. Scripts（脚本）

一个可执行文件就是一个工具：顾清影 从文件开头的注释读工具契约（描述、参数 schema、超时、分组），用 JSON 传参把它跑起来。完整接口说明见 `docs/scripts/README.md`，模型侧的同一份契约在内置技能 `script-creator` 里。

### 目录（同 id 后者覆盖前者）

| 目录 | 说明 |
|---|---|
| `<安装前缀>/share/gqy/scripts/personas/default/` | 内置脚本（源码 `src/scripts/personas/default/`，`GQY_SYSTEM_SCRIPTS_DIR` 可覆盖）。默认人格全挂；自定义人格只挂人格清单 `plugins.scripts` 里点了名的 |
| `~/.gqy/extensions/scripts/` | 全局用户脚本（旧布局没迁完时是 `~/.gqy/data/scripts/`） |
| `~/.gqy/extensions/scripts/personas/<人格>/` | 人格专属脚本，`manage_script` 默认落在这里，不受白名单管（私有人格在 `home/<user>/personas/<名>/scripts/`） |

### 头部即契约

```
#!/usr/bin/env python3
# Display name: 番组日历
# Description: Query the Bangumi airing calendar. Use for "what airs today" questions.
# Timeout: 60
# Group: research
# Parameters:
# {"type": "object", "properties": {"query": {"type": "string", "description": "keyword"}}}
```

`Description` 英文、首句 ≤60 字符；`Parameters` 是 JSON Schema，可多行；`Id` 可覆盖由文件名推出的工具名（`battery-care` → `battery_care`）；`Argv: flags` 让参数额外展开成 `--key=value`；`Platform: macos`（或 `linux`，可逗号分隔多个）声明只在该系统上跑，别的系统扫描时当它不存在。其余可选键还有 `Trust`、`Permission`、`Example`、`Hint`、`Requires`，解析在 `src/tools/scripts/header.rs`。传参默认是 stdin 上的一个 JSON 对象，同一份也在环境变量 `GQY_ARGS_JSON` 里。

### index.json 是覆盖层

每层目录可有 `index.json`，条目里显式写的字段压住头部、没写的从头部补；`disabled` 名单屏蔽本层及更低层的同名脚本（内置脚本只能这样屏蔽）。内置脚本已全部迁到头部（09-05），不再带 index.json；`manage_script` 只把你显式传的覆盖字段写进 index。

### 注册与安全

- AI 用 `manage_script`（action=register，`path` 给任意绝对路径）注册：文件被复制进当前人格目录、设可执行位，下一个工具回合即可调用；`action=list` 列出已注册/未注册/禁用；`action=unregister` 屏蔽或删除。
- 直接放进目录的文件只要有 shebang 和 `# Description:` 头部就会被自动检测；缺描述的只出现在 `unregistered` 列表，不会成为工具。目录一变下一回合自动重扫。
- WebUI 设置 → 插件 →「扩展」页也列出脚本、技能、MCP 服务器和 pm 包，脚本开关沿用下面这套接口。
- WebUI 控制台有「脚本」面板（09-05）：列出四层里全部脚本工具（所在层、参数、超时、分组、加载方式、argv），点开看描述来源、schema 与文件开头；可禁用/启用/删除，未注册文件可当场补一句描述登记。接口 `/api/dash/scripts/*`，写操作与 `manage_script` 同一套逻辑。
- 脚本默认按需加载（`load_tools` 目录可见），index 里 `always_loaded: true` 可强制常驻。
- 脚本执行受超时（默认 120s，上限 300s）、8 MiB 输出硬上限、20000 字符展示软上限约束；脚本路径必须在脚本目录内。
- QQ 受限平台没有脚本工具。
