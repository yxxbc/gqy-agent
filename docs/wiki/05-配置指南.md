# 05 · 配置指南

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 顾清影 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `gqy -h`、`gqy config`、仓库 README 及源码为准。

## 1. 配置在哪里

| 项 | 位置 |
|---|---|
| 主配置 | `~/.gqy/config/config.jsonc`（JSONC，允许注释） |
| 默认人格 | `~/.gqy/data/prompts/system-prompt.md` |
| 开发模式提示词 | `~/.gqy/config/dev-prompt.md`（旧资源布局） |
| 用户身份 | `~/.gqy/home/<用户名>/identities/user-identity.md`（老布局在 `data/identities/`） |
| 自定义人格 | `~/.gqy/data/prompts/` 下每个 `.md` 一个人格；人格清单等在 `~/.gqy/personas/<人格>/` |
| 技能 | `~/.gqy/extensions/skills/`（老布局 `data/skills/`） |
| 脚本 | `~/.gqy/extensions/scripts/`（老布局 `data/scripts/`） |
| WebUI 配色主题 | `~/.gqy/config/webui-themes/*.css` |

以本机 `gqy paths` 的输出为准；老布局可用 `gqy layout` 查看搬家计划、`gqy layout --apply` 迁到新布局（详见 [11-数据与目录](11-数据与目录.md)）。

> 老版本曾使用 XDG 目录（`~/.config/gqy`、`~/.local/share/gqy` 等）。新版启动时会自动迁移到 `~/.gqy`，迁移失败会拒绝启动且**零写入**。设置 `GQY_HOME` 可整体换位置。

推荐用 TUI 修改：

```bash
gqy config
gqy config validate
gqy config paths
```

主菜单依次是：供应商和模型、配置全局文本模型、配置全局多模态模型、配置 Embedding 模型、配置分级模型池、插件配置、自定义提示词、接入通讯平台，然后是六个全局设置分组（显示、工具、上下文、缓存、通知、成员账号，与 WebUI「设置 → 全局」对应），再是语音功能、保存并退出。`j/k` 移动，`Enter` 进入，`q/Esc` 退出；退出时有改动会询问是否保存。REPL 里 `/config <分组>`（`display` / `tools` / `context` / `cache` / `notifications` / `accounts`，中文名也认）直接打开一组。

WebUI 的同类设置在「控制台 → 设置」：界面 / 人格 / 供应商 / 模型池 / 全局 / MCP / 插件 / 高级；「全局」页再分「工具 / 对话 / 记忆 / 语音与通知 / 账号与平台」标签。

## 2. 供应商与模型

### 核心概念

- **供应商（provider）**：一个 API 端点。内置 11 个模板（含 opencode、DeepSeek、OpenAI、Anthropic、Moonshot、Qwen、GLM、taotoken 等）。
- **默认供应商** `active_provider`：默认是 `opencode`（opencode zen 公共端点）。
- **文本模型池** `active_provider_models`：`None` = 跟随当前供应商的 `default_model`；`Some` = 启用多选池，CLI 可 `gqy models` 切换。
- **多模态模型池**：识图时用；未配置时按“显式 vision provider → 活跃多模态池 → opencode 默认 vision 模型”回退。
- **Embedding**：语义检索（知识库、记忆联想、表情包、被淘汰上下文的辅助排序）。默认开启并使用内置本地模型 `bge-small-zh-v1.5-int8`（跑在独立子进程里，空闲 10 分钟自动退出；需要系统的 ONNX Runtime 库，Arch 装 `onnxruntime-cpu`）。`embedding.backend` 为 `auto/local/remote`，配了远程供应商模型且为 auto 时优先远程；`embedding.enabled=false` 整体关闭，只剩关键词检索。

### Provider 字段

| 字段 | 说明 |
|---|---|
| `id` | 唯一标识（配置里大量引用它） |
| `display_name` | 显示名 |
| `base_url` | API 根地址 |
| `protocol` | `auto` / `openai-chat` / `openai-responses` / `anthropic`（内置 Claude Code 条目内部使用 `claude-code`，不在表单下拉里） |
| `api_key` | 支持 `$env:变量名` 和逗号分隔多 key（多 key 自动轮转/冷却） |
| `models` | 模型清单，可写 `context_window`、`temperature`、`modalities`、`cost`、reasoning |
| `default_model` | 默认模型 |
| `timeout_seconds` | 会被 clamp 到 5–30 秒 |
| `extra_body` | 透传 JSON 对象（保留字段会防覆盖） |
| `anthropic_max_tokens` | Anthropic 协议 max_tokens 上限 |
| `tool_result_media` | 工具结果（role=tool）能否直接带图片/视频块。留空按协议推断：openai-chat 端点默认能（智谱实测），OpenAI 官方端点、内置 CLI 中转与 anthropic 协议不能。不能的走"工具结果之后补一条带图的用户消息"。当前模型自己看图时 `vision_analyze` 就靠这条把原图交给它 |

温度覆盖顺序：模型温度 → 供应商温度 → 默认 1.0。上下文窗口：模型配置 → 在线模型缓存 → 默认 168000；多模型激活取**最小值**。

### 协议自动判断（不需要你操心）

- 模型是 gpt-5/o 系列或显式 `openai-responses` → Responses API。
- provider 名/URL 像 Anthropic 或显式 `anthropic` → Messages API（带 `x-api-key` + `anthropic-version: 2023-06-01`）。
- 其他 → Chat Completions。
- DeepSeek 白名单 provider 才回传 `reasoning_content`；taotoken + glm 会传 `enable_thinking`。
- `claude-code` / `antigravity` / `codex` 永远不会被自动猜到，必须显式配置（见下三节）。

### Claude Code 订阅接入（内置特殊供应商）

把本机已订阅登录的 Claude Code CLI 当供应商用：顾清影 的请求经 `claude -p` 子进程
（stream-json 双向流）出去，走订阅额度，顾清影 不经手任何凭据。

它**不是**你手动添加的 HTTP 供应商：供应商列表里天生就有「Claude Code」这一
项，**默认未启用**。在「供应商和模型」里选中它回车，会打开专用编辑表单——
只有启用总开关、显示名、claude 可执行文件路径、工具桥开关和流空闲看门狗，
没有 base_url/协议/API Key/超时/额外请求体这些对它没有意义的字段。启用开关
是**总开关**：同时决定订阅中转可选与 `claude_code` 委托工具注册。

模型列表预置 CLI 认识的别名 `fable` / `opus` / `sonnet` / `haiku`（默认
sonnet），照常在模型菜单勾选进文本模型池。每个模型有思考档
`low / medium / high / xhigh / max`，映射到 CLI 的 `--effort`，用
`gqy variant` 或模型菜单切换。

要点：

- 未启用时不进任何模型选择器；激活池指到它会得到明确的「供应商未启用」报错。
- 系统提示词（人格/开发提示词）经 `--system-prompt` 整体替换，claude 自带的
  CLI 身份与 CLAUDE.md 不会注入。
- **工具循环在 claude 侧闭环**，工具面由两个四档作用域（`off/dev/normal/all`，
  在专用表单里改）决定：
  - **Claude 原生工具**（Bash/Edit/Read…，默认 `all`）：训练分布内、编码能力
    最强；开启时按表单里的权限模式跑（默认 `bypassPermissions`——无头模式没
    有交互审批，不 bypass 则 Bash 被拒），工作目录是会话工作区；
  - **顾清影 工具经 MCP 桥**（默认 `all`）：经 `gqy mcp-serve` 打回 daemon，
    内层调用照走 guard/超时管线；工具图片/artifact 照常落资产并实时推给
    REPL/WebUI 渲染，ask_question 走既有问答弹窗。两个作用域可叠加；**同时
    开启时自动去重**——与原生重复的 顾清影 工具（read_file/apply_patch/
    run_command/web_search/web_fetch/glob/grep/todowrite）剔除，原生优先；
    **task/job/alarm 保留**：claude 自带的后台与定时活在单次进程里、轮末即
    杀，顾清影 的 task（daemon 后台子代理+完成唤醒跟进）/job（查停）/alarm
    才是这套架构下能跟进的版本，系统提示词里也注入了这条环境事实。
- **会话续传**：同一会话内按 append-only 前缀链匹配自动 `--resume`，每轮只发
  增量；redo/compact/重启后自动整段重放，不损失正确性。不同 顾清影 会话严格
  映射到不同 claude 会话；**清空/删除 顾清影 会话会联动**丢弃映射并删除
  claude 侧的会话转录。
- **平台回合同样可用**：它就是一个普通的供应商/模型，QQ 等平台会话命中时照常
  中转（08-20 起，早期的"仅限本机"门禁已撤销）。订阅限流按 429 处理
  （600s 冷却 + 故障转移）。
- 温度不透传；用量按 Anthropic 口径记账，订阅无按 token 计费，成本列仅供参考。
- 中转相关设置在专用表单里改，落盘于 `plugins.claude_code`：`binary`（空 =
  PATH 上的 claude）、`native_tools`/`gqy_tools` 双作用域、`permission_mode`、
  `idle_timeout_seconds`（注意：原生工具跑长时间无输出的命令会撞看门狗，需要
  的话调大）；另有仅文件可改的 `prefer_subscription`（剥离环境里的
  ANTHROPIC_API_KEY，强制走订阅）与委托工具专用的
  `timeout_seconds`/`max_output_bytes`。

### Antigravity（agy CLI）接入（内置特殊供应商）

把本机已登录的 Google Antigravity CLI（`agy`）当供应商用，形态与 Claude Code
完全同构：请求经 `agy --print= --input-format stream-json` 子进程出去，走 Google
的额度，顾清影 不经手凭据。供应商列表里天生有「Antigravity」（排在 Claude Code
之后），**默认未启用**，回车打开专用表单：启用总开关、显示名、agy 可执行文件、
原生工具/顾清影 工具两个四档作用域、桥工具 eager 开关、流空闲看门狗、
`--print-timeout`、预热进程保留时长。落盘于 `plugins.antigravity`。

**预热**（`warm_idle_seconds`，默认 300）：每轮都是新起一个 agy 进程，其中约 6 秒
花在进程自己的启动上。常驻 daemon 会在一轮结束后把下一轮的 agy 提前拉起来晾着，
下一轮直接用，这 6 秒就省掉了。只晾一个，超过这个秒数没人用就自动关掉；设成 `0`
完全不预热。换了会话、发起来源或续传目标都不会复用晾着的那个，退回冷启动。

模型列表预置 `agy models` 的输出（gemini-3.8-flash-high/medium/low、
gemini-3.1-pro-*、claude-sonnet-4-6、claude-opus-4-6-thinking、gpt-oss-120b-medium，
默认 gemini-3.8-flash-high）；gemini/gpt-oss 的思考档编码在模型名后缀里，只有
claude-* 模型有 `low/medium/high` 三档映射到 `--effort`。

与 Claude Code 线的差异（都是 agy 的形态决定的）：

- **人格不走命令行参数**：agy 没有 `--system-prompt`，顾清影 把系统提示词写成
  全局自定义代理 `~/.gemini/config/agents/gqy/agent.md`（正文整体替换 agy 的
  默认指令，提示词变了才改写），每轮 `--agent gqy` 挂上并校验 init 事件里的
  代理名——没挂上会报错而不是静默跑在 agy 默认提示词上。你在交互式 agy 的
  `/agents` 面板里会看到这一条。
- **原生工具面靠代理文件的 `tools:` 白名单**：`run_command / view_file /
  write_to_file / replace_file_content / find_by_name / grep_search / list_dir /
  read_url_content / search_web`。故意不列 `ask_question`（无头模式下它会被瞬间
  跳过）和 `generate_image`（原生生图的图片进不了 顾清影 的图片通道），这两件只
  留桥版。原生工具一律 `--dangerously-skip-permissions`（不放行则命令被拒且
  agy 仍报成功），工作目录经 `--add-dir` 钉在会话工作区。
- **顾清影 工具桥只能全局注册**：`~/.gemini/config/mcp_config.json` 里的 `gqy`
  条目由 顾清影 维护（只动这一个键），会话身份经 agy 进程环境继承给
  `gqy mcp-serve`；条目里带 `GQY_MCP_REQUIRE_SESSION=1` 守卫——你自己交互式
  开 agy 时没有会话身份，桥只应答空工具表。桥工具默认 eager 注册（以
  `mcp_gqy_<name>` 原生名直调，schema 进系统提示词，**每轮提示词约 4–5 万
  token**）；关掉 eager 走 agy 的懒加载省 token 但每件工具首次多一步读 schema。
  Gemini 对工具 schema 校验很严，桥会按 Gemini 方言整形（去空 enum、折联合类型、
  剔 additionalProperties 等键），工具自己的 schema 不改。
- **去重名单**：原生开启时从桥上剔除 `run_command / web_search / web_fetch /
  glob / grep`；`todowrite`（agy 没有对应物）、`read`/`edit`（kb:/artifact: 域）、
  `task`/`job`/`alarm`（daemon 常驻后台）保留。
- **续传**：同一 顾清影 会话按前缀链自动 `--conversation <id>` 只发增量。agy 在
  续传目标不存在时**不报错而是静默新开会话**，顾清影 以 init 首行的 id 比对判定并
  立刻重放整段。清空/删除 顾清影 会话（含一次性会话结束）联动删除 agy 侧的
  `conversations/<id>.db*` 与 `brain/<id>/`。
- 思考内容不外露（只有 token 计数）；图片进不了 agy（stdin 只收文本）；没有
  `--autocompact`，顾清影 侧 compact 后照常新会话重放。
- **缓存命中率**：agy 报的 `cache_read_tokens` 经常等于整个 prompt（本轮新输入
  不可能已被缓存，物理上不成立），顾清影 把这种「整段命中」按未报告处理，页脚不
  画 C%；部分命中照实显示。订阅额度不按 token 计费，这个数只影响观感。

### Codex（OpenAI codex CLI）接入（内置特殊供应商）

第三条本机 CLI 中转线，用本机已登录（`codex login`，ChatGPT 账号）的 `codex`。
供应商列表里排在 Antigravity 之后，**默认未启用**；专用表单：启用开关、显示名、
codex 可执行文件、原生/顾清影 两个四档作用域、沙箱模式、是否忽略用户自己的
`~/.codex/config.toml`、看门狗。落盘于 `plugins.codex`。模型预置 `codex debug
models` 的目录（gpt-5.6-terra/sol/luna、gpt-5.5、gpt-5.4、gpt-5.4-mini、gpt-5.2，
默认 gpt-5.6-terra），思考档 `minimal/low/medium/high/xhigh` 映射到
`model_reasoning_effort`。

它是三条线里最干净的一条，因为 codex 的任何配置都能经 `-c key=value`
**逐进程**注入：

- 人格经 `model_instructions_file` 整体替换内置指令（指令文件按内容哈希落在
  `state/relay/codex/`），`project_doc_max_bytes=0` 让工作区的 AGENTS.md 不进
  上下文；默认 `--ignore-user-config`，用户自己的 MCP 服务器/规则不会混进来。
- 顾清影 工具桥也是逐进程的 `-c mcp_servers.gqy.*`，不写任何全局文件；桥问答
  超时设 1800 秒。去重名单：`run_command / web_search / todowrite`（codex 的
  shell、web search、update_plan）。
- 原生工具没有白名单，`native_tools` 关掉时按功能开关尽力关 shell 与网页搜索。
- 沙箱默认 `danger-full-access`（与另两条线的全放行同义，用
  `--dangerously-bypass-approvals-and-sandbox`）；改 workspace-write / read-only
  则走 codex 自己的沙箱加 `approval_policy=never`。
- 续传 `codex exec resume <thread_id>`；目标丢失时 codex 报 `no rollout found`，
  顾清影 忘掉映射整段重放。清空/删除 顾清影 会话联动删 `~/.codex/sessions/` 下的
  rollout。辅助请求加 `--ephemeral`，不落盘。
- 正文不流式（一条 agent_message 一次到齐），思考摘要进思考通道；图片进不了
  stdin（codex 有 `-i` 传图，暂未接）。

### Cline（cline CLI）接入（内置特殊供应商）

第四条本机 CLI 中转线，用本机已登录（`cline auth`）的 `cline`。供应商列表里排在
Codex 之后，**默认未启用**；落盘于 `plugins.cline`：可执行文件、`-P` 显式供应商
id（留空 = 用 CLI 默认的那家）、原生/顾清影 两个四档作用域、看门狗。**模型目录
问 cline 本体要**：从 `cline` 可执行文件（解开符号链接后）向上找到它自带的
`@cline/llms`，用 node 打印 `getModelsForProvider(<供应商 id>)` 的键——与 cline
TUI 的模型选择器同源（`cline` 317 个、`cline-pass` 18 个这类），「拉取模型列表」
在 TUI / WebUI / 引导里都能用；**目录带回的上下文窗口会在该模型被激活/补全时
自动填进 `model_context_window`**（进程内缓存，不再多跑一次 CLI）。预置表为空，
目录拉不到时仍可手工添加模型，找不到 node 或包会直接报错。思考档
`none/low/medium/high/xhigh` 映射到 `--thinking`。

几处与另三条线不同的地方，都是 cline CLI 的形态决定的：

- **提示词走命令行参数**（这一版 `--json` 不收 stdin），单轮载荷因此有 96 KiB
  预算（Linux 单参数上限 128 KiB）：超了从最老的历史丢起，本轮输入永远保留。
- **人格经 `-s` 整体替换**系统提示词，工作目录经 `-c` 指定，工具调用默认
  全部自动批准（与另三条线的全放行同义）。
- **顾清影 工具桥**经 `CLINE_MCP_SETTINGS_PATH` 指向的临时配置文件挂进去
  （只含 `gqy` 一条，收口即删）：用户自己的 MCP 服务器不进中转，与 claude 线的
  `--strict-mcp-config` 同义；两套同开时的去重名单与 claude 线相同。
- **续传**：CLI 不在事件流里报会话 id，用 `~/.cline/data/sessions/` 下会话文件的
  `prompt`/`cwd` 发现、mtime 核对。首轮全量重放后按 `prompt` 找到会话，之后
  `--id` 只发增量；一旦核对该会话没有被本轮写过（CLI 没兑现 `--id`），就忘掉
  这条链并**关掉该供应商的续传**（daemon 生命周期内全量重放）——宁可多花
  token，不冒"静默丢历史"的险。
- 图片/视频等媒体消息转成占位文本（中转层是纯文本）；模型要看图得靠它自己的
  文件工具。辅助请求（压缩/标题/判官）也会在 cline 侧落一个会话（CLI 没有
  类似 `--ephemeral` 的旗标）。

### 思考档位（thinking variant）

配置模型时可给每个模型定义思考程度（如关闭/省流/深度）。选择按 `provider_id\tmodel` 持久化在 `state/thinking-variants.json`。CLI `gqy variant` 和 WebUI 模型菜单都可切换。

### 分级模型池

`model_tiers`（旧键 `subagent_tiers` 继续可读，保存时写新键）：`lite` / `cheap` / `standard` / `flagship` 四档，中文 轻量 / 便宜 / 普通 / 旗舰，每档是一个和全局文本池一样的多选池，请求时轮询。档位不影响工具集。旧档位名 `balanced` / `strong` 作为别名继续可读。

| 档 | 放什么 |
|---|---|
| lite | 白嫖来的、能力一般的模型，干单发小活：会话标题、日记整理、QQ 回复判定、入群审批 |
| cheap | 便宜但能稳跑工具循环的模型 |
| standard | `task` 子代理的默认档、日记整理默认 |
| flagship | 难推理 |

用法有三处：

- **`task` 工具**：主模型按任务难度自选 `tier`（默认 standard）。未配置的档位回退全局文本池；配了但不可用（模型被删、供应商停用）也回退，并在工具结果里附一句说明。
- **旁路请求** `model_tiers.roles`：`session_title`（会话标题）、`memory_organizer`（日记整理）、`selection_assist`（WebUI 选中文字右键的「解释 / 翻译」）、`chat_review`（聊后复盘）各指一档；缺省值随代码内置（`session_title` 与 `selection_assist` 是 lite，`memory_organizer` 与 `chat_review` 是 standard），写 `global` 显式走全局池。没配任何档位时行为与从前一致；一旦配了 lite 池，标题和整理自动搬过去。角色名或档位名写错，启动直接报错并列出可选值。compact 不在角色表里：它复用主对话的缓存前缀，必须留在主池。
- **通讯平台的配置模型**：QQ 各处的池可以直接指向某一档，见 wiki 13。

```jsonc
"model_tiers": {
  "lite":  [ { "provider_id": "sensenova", "model": "SenseChat-5" } ],
  "cheap": [ { "provider_id": "deepseek",  "model": "deepseek-chat" } ],
  "roles": { "memory_organizer": "flagship", "session_title": "global" }
}
```

TUI：主菜单「配置分级模型池」，四档与两个旁路请求平铺一屏，Enter 打开（档位是多选框，旁路是档位单选），`d` 把旁路行清回缺省。WebUI：模型池页六列矩阵加「旁路请求」卡片。

## 3. 人格与身份

### 系统提示词优先级

`active_persona` 指定的人格文件 → `config.system_prompt` → `custom_system_prompt`。默认人格（`system-prompt.md`）在构建时 XOR 混淆进二进制，用户覆盖后以文件为准。

- **人格文件**放在 prompts 目录，`gqy config → 自定义提示词` 可新建/编辑/删除。
- 人格改名会同步更新 StateStore 里的会话归属；被会话引用的删除会被拒绝。
- **hints/dialogs**：人格可带 `gqy.hint.md` 风格提示和示例对白文件。
- **用户身份**：`user-identity.md`，只有 Owner（终端/WebUI 本地）场景注入，External（QQ 群）不注入。
- **persona reminder**：每 N 轮（默认 3）注入一次蒸馏后的人格提醒；空文件 = 显式停用。
- **Dev 模式**：默认提示词就是一句 “You are a helpful software engineer assistant.”，用户可覆盖 `dev-prompt.md`。

### 平台人格路由

QQ 的每个会话（conversation）可以绑定特定 persona 和模型池；未绑定按全局。普通终端和开发模式永远隔开。

## 4. 插件开关

配置 TUI 的“插件配置”页可以开关 10 个内置插件，最后一行「扩展」列出技能、脚本工具、MCP 服务器和 pm 包（技能、脚本空格即生效；MCP 随保存写回；pm 包只读，升级/卸载用 `gqy pm upgrade` / `gqy pm remove`）。WebUI「设置 → 插件」有同样的「扩展」分组，并多了详情、新建技能、检查更新等（见 [06](06-内置工具与插件.md)）。常见默认值：

| 插件 | 默认 | 说明 |
|---|---|---|
| archlinux（含 AUR 审查安装） | 开 | 基础日用。天气、玄学、萌娘百科、编解码、计算器、在线手册这几件已改成内置脚本，不再有开关：要禁用就在脚本目录的 `index.json` 里 `disabled` 掉 |
| web（网络搜索/抓取） | 开 | 未配 key 也能用爬虫回退 |
| web_images（搜图） | 开（开关 true），但源配置按需 | 下载图片默认 4 MB/张上限 |
| vision / print_image | 开 | 识图与终端显示图片 |
| image_generation | **关** | 需自己配 OpenAI/RightCode 生图 API |
| exchange_rate | 关 | 配 key 开（开关在 WebUI「设置 → 插件」，不在 TUI 插件页） |
| api_quota | 开 | 查询 DeepSeek/OpenRouter 余额 |
| memes | 开 | 表情包 |
| knowledge_base | 开 | 知识库功能 |
| memory | 开 | 记忆功能 |

> 插件字段在 TUI 中是固定顺序表单；改配置 JSON 时注意不要写错键名。

## 5. 上下文与工具行为

### context（上下文管理）

| 项 | 默认 | 说明 |
|---|---|---|
| `context_window` | 168000 | 默认模型窗口 |
| `tool_output_spill_bytes` | 50000 | 超长工具输出落盘，上下文只留头尾预览 |
| `trim_at_ratio` | 0.8 | 到达窗口 80% 时准备裁剪 |
| `trim_batch_ratio` | 0.15 | 一次释放窗口的 15% |
| `on_overflow` | compact | 溢出策略：compact（压缩）或 pop（弹出旧轮） |
| `compact_force_ratio` | 0.9 | 强制压缩线（绕过折叠经济性闸门） |
| `compact_cache_reuse` | true | 压缩时复用实况前缀，保住前缀缓存 |
| `compact_restore_files` | 5 | 压缩后从磁盘重读回上下文的文件数（最近碰过的优先）；0 = 关闭 |
| `compact_restore_file_tokens` | 4000 | 单个回灌文件的 token 上限，超了只留路径 |
| `compact_restore_total_tokens` | 24000 | 一次回灌的总 token 预算，另受上下文窗口 1/8 封顶 |
| `compact_transcript_export` | true | 把折叠掉的对话写成 Markdown 转录（`state/compact/<会话>/`），供她读回细节 |

压缩相关的实验开关（环境变量，不进配置文件）：

| 变量 | 作用 |
|---|---|
| `GQY_COMPACT_PROMPT_FILE` | 用指定文件替换摘要提示词底稿（A/B 实测用） |
| `GQY_COMPACT_ANALYSIS=1` | 打开摘要前的分析段（**默认关**）。它让模型先写一份草稿再写摘要：输出量翻倍，而草稿不会显示给你，屏幕上会先空白一大段。实测没提升召回，长会话配慢模型还会把压缩拖过超时线 |

### tools

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `loading_mode` | stub | stub = 懒工具常驻“摘要壳”，缓存最友好；hybrid = 按需加载 |
| `persist_loaded_tools` | true | 会话内记住已加载工具 |
| `max_rounds` | 0 | 单轮最大工具轮数，0 无限 |
| `subagent_concurrency` | 4 | 并行 task 波次 |
| `default_timeout_secs` | 180 | 工具超时；0 关闭 |
| `command_deny` | 默认 5 条 | 命令黑名单子串 |
| `github.enabled` | true | `github` 工具开关 |
| `github.coauthor_name` | 顾清影 | `Co-Authored-By` 的名字。issue / PR 正文里会渲染成指向项目主页的链接，commit 里保持纯文本 |
| `github.coauthor_email` | 空 | trailer 邮箱；留空时登录了 bot 用它的 noreply 邮箱（GitHub 才挂头像、计贡献），否则用 `gqy-agent@noreply.invalid` |

`github` 工具缺省用你自己的 gh / git 身份；要让 顾清影 用自己的账号，先 `gqy github login`（凭据写在 `~/.gqy/github/`，不碰 `~/.config/gh`、`~/.gitconfig`、Keychain），再明确告诉它“用你自己的账号”。`/sandbox` 会话里用 bot 需把 `~/.gqy/github` 加进 `tools.sandbox.writable`。

### cache（高级）

| 项 | 默认 | 说明 |
|---|---|---|
| `keepalive_seconds` | 0 | 每 N 秒重发 1-token 保温 ping，续住 DeepSeek 类热缓存；**按请求次数计费的网关勿开** |

详见 [13-QQ与通讯平台](13-QQ与通讯平台.md)。核心项：

## 8. 保存与热重载

- `config.jsonc` 原子写入：临时文件 + persist，不会写坏。
- 保存时自动 normalize：补内置供应商、清理失效模型引用、迁移旧路径、把顶层 memory 复制到 plugins.memory。
- daemon 运行时保存配置会自动请求 reload；忙时重试。
- 人格布局变化会中断正在运行的回合，避免旧上下文继续跑。

## 9. 配置校验规则（常见报错）

- 比例必须满足 `compact_force_ratio ≥ trim_at_ratio`。
- `on_overflow` 只接受 pop / compact。
- 温度 0.0–2.0；provider id 不能重复/空白。
- QQ 端口不能为 0；限流窗口 1–86400 秒。
- 思考档位只接受 minimal/low/medium/high/xhigh。
- 记忆参数：`diary_batch` 2–100，`short_retention` 1–3650 天等。
- 聊后复盘：`plugins.memory.review_idle_seconds` 为 0（关闭）或 300–86400 秒，默认 900。对话安静这么久后，她在后台复盘这段对话，下一轮起按复盘结果调整说话方式。只对属主的终端与 WebUI 会话生效；下限 300 秒是为了不在缓存还热时换掉 system 提示词。
