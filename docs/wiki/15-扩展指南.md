# 15 · 扩展指南

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 顾清影 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `gqy -h`、`gqy config`、仓库 README 及源码为准。

顾清影 提供了五层扩展入口，从“完全不用写代码”到“写协议适配器”，按成本排序。

## 1. 不改代码的扩展（推荐先试）

| 想加什么 | 怎么做 |
|---|---|
| 新知识 | `gqy kb add`，或直接让 AI 用 `edit` 往 `kb:` 命名空间写文件 |
| 新流程/能力 | 让 AI `manage_skill`（action=create → 草稿 → action=publish），按 `src/skills/skill-creator.md` 规范 |
| 新脚本工具 | 让 AI 按 `script-creator` 技能写脚本（头部注释即契约，只在某个系统能跑的加 `# Platform: macos` 或 `linux`），`manage_script`（action=register，path 给任意路径）自动复制进脚本目录；接口见 `docs/scripts/README.md` |
| 新表情 | 给 AI 图片路径，`manage_meme`（action=add）自动识图入库 |
| 新人格 | `gqy config` → 自定义提示词 → 新建 persona |
| 新主题 | 让 AI 按内置技能 `webui-theme` 写 `~/.gqy/config/webui-themes/<名字>.css`（只覆盖 CSS token，不开放 JS），在设置 → 界面 →「配色方案」里挑；matugen 生成的单文件仍可放 `~/.gqy/config/webui-theme.css` |
| 新 MCP 工具 | 配置 `mcp.servers`（stdio server），工具自动注册 |

## 1.5 打包与安装扩展(`gqy pm`)

一个包 = 一个仓库(GitHub)或本地目录,根上一份 `gqy-package.toml`:

```toml
[package]
name = "bangumi-tools"          # 小写字母、数字、- _;2–64 位
version = "1.0.0"
description = "番组日历与搜索"
kind = "extension"              # extension(缺省)或 persona
requires-gqy = ">=0.5.0"       # 可选,只支持 >=

[install]                       # 都可省,下面是缺省值
scripts = ["scripts/*"]         # 脚本文件(头部契约见 docs/scripts/README.md)
skills = ["skills/*"]           # 技能目录,每个里面要有 SKILL.md
persona = "persona"             # kind = persona 时的人格目录
```

- `extension` 包的脚本装到 `extensions/scripts/`、技能装到 `extensions/skills/<名>/`,所有人格可见。
- `persona` 包:`persona/persona.md` → `data/prompts/<包名>.md`(人格提示词),可选 `persona.json`(头像/看板等元数据,路径相对 `persona-avatars/`)、`persona.toml`(启用集)→ `personas/<scope>/persona.toml`、`assets/` → `persona-avatars/<包名>/`;包里的脚本与技能只给这个人格(`extensions/{scripts,skills}/personas/<scope>/`)。
- 命令:`gqy pm install <包名|owner/repo[@ref]|GitHub URL|本地目录>`(装前摊开文件清单再确认,`-y` 跳过)、`remove`、`upgrade`(commit 或内容指纹没变就不动)、`search`、`list`、`tap add|remove|list`。`gqypm` 是同一套(argv[0] 识别,打包做个符号链接)。
- 索引:tap 是一个 GitHub 仓库,根上 `index.json`:`{"packages": {"bangumi-tools": {"repo": "owner/repo", "description": "…", "kind": "extension"}}}`。没有内置的默认 tap，要按包名安装先 `gqy pm tap add owner/repo`；不加 tap 也能直接按 `owner/repo`、GitHub URL 或本地目录安装。
- 锁文件 `extensions/pm/lock.json` 记来源、commit、版本、装进来的每个文件与内容指纹;卸载按它删,目标文件被别的包占着或不是 pm 装的会拒(`--force` 覆盖)。只往 `extensions/`、`personas/`(以及人格的 `data/prompts`、`data/persona-avatars`)写。装完通知 daemon 重载;脚本目录变了下一回合自动重扫。
- 升级拆成两步(`src/pm/upgrade.rs`):`prepare` 抓取并比对,`apply` 执行;命令行在两步之间问确认,WebUI 的升级按钮直接连着调。
- 不做:签名、沙盒、二进制包、MCP 配置片段(这些留给以后)。

## 1.6 管理已装的扩展

WebUI 设置 → 插件 →「扩展」(`web/settings-extensions.js`,接口 `/api/extensions*` 在 `src/web/extensions_api.rs`)和终端 `gqy config` 的扩展页(`src/config_tui/extensions.rs`)把技能、脚本、MCP 服务器、pm 包列在一起:

- **技能**:列出含已关闭在内的全部技能(`src/skills/admin.rs`)。开关分三种:平台级内置技能 `fixed` 不能关;人格自己那一层用目录里的 `.disabled` 标记;全局层与可选内置技能写进当前人格清单的 `plugins.skills` 白名单。改完下一轮按指纹重扫生效。
- **脚本**:开关与删除沿用控制台脚本面板的 `/api/dash/scripts/*`。
- **MCP**:开关改的是配置草稿,点「保存配置」才生效;抽屉里显示本进程最近一次列举到的工具或失败原因(`tools/mcp.rs` 的 `listing_status`)。
- **pm 包**:抽屉里升级、卸载;安装要下载外部代码,仍走命令行。
- **来源与更新**(`src/pm/origin.rs`):每项标出来源——git 克隆来的、pm 包、自己创建、内置,或由别的程序管理。直接 `git clone` 进来的技能目录与 MCP 服务器能「检查更新 / 一键更新」:查远端默认分支的最新提交,在分支上就快进,分离头指针就切到新提交,再按目录里的文件同步依赖(npm / pnpm / yarn、uv / pip);已跟踪文件有本地修改时拒绝更新。

## 2. 新增一个 Rust 内置工具

步骤：

1. 新建 `src/tools/my_tool.rs`，实现：

```rust
pub fn register(registry: &mut ToolRegistry, config: AppConfig) {
    registry.register(
        ToolSpec::new(
            "my_tool_name",
            "占位描述（注册时被 JSON 整体覆盖）",
            serde_json::json!({ "type": "object", "properties": {} }),
            |args| async move {
                // 返回 Result<String>
                Ok("ok".to_string())
            },
        )
        .writes(), // 只读就不要；presentation() 是第三档
        // display_name / always_loaded / load_policy / groups / timeout
        // 全部写在 descriptions JSON 里，注册时自动覆盖，代码里不用再设。
    );
}
```

2. 在 `src/tools/mod.rs` 顶部加 `mod my_tool;`，并在 `src/tools/compose.rs` 的注册单元表 `UNITS` 里按位置加一行 `Unit { plugin, when, register }`（三个面 Normal / Dev / QQ 受限都从这张表装出来）：
   - 属于某个内置插件：`plugin: Some("插件 id")`，并在 `src/config/plugin_catalog.rs` 的 `PLUGINS` 里加一行（`plugin(...)` 常开或 `toggle(...)` 引导里给开关：id、显示名、一句话说明）。两边对不上时 `plugin_units_match_the_plugin_catalog` 报红。
   - core 或子系统工具：`plugin: None`，条件写在 `when`。
3. ~~在宏里加 `include_str!`~~：不需要了，build.rs 扫 `descriptions/` 目录自动登记。注册了却没有 JSON 的工具由 `registered_built_in_tools_have_json_descriptions` 报红。
4. 新建 `src/tools/descriptions/my_tool_name.json`：

```json
{
  "name": "my_tool_name",
  "display_name": "我的工具",
  "description": "……",
  "parameters": { "type": "object", "properties": {}, "required": [] },
  "always_loaded": false,
  "load_policy": "summary",
  "groups": ["utility"],
  "timeout_seconds": 30
}
```

5. 在 `tools/mod.rs` 的 `builtin_readable_tool_name` 加中文名；新组在 `builtin_readable_group_name` 加组名，并加到 `descriptions/groups.json`。
6. 若需要配置开关，在 `config/tool_plugins.rs` 的 `PluginsConfig` 加字段、默认值（`config/defaults.rs`）、校验（`config/io.rs`）、TUI 表单（`config_tui/plugins.rs` 的 `plugin_fields`）。
7. 若需要子代理继承，`UNITS` 里的位置要排在 subagent 那一行（`let mut subagent_tools = registry.clone();` 取快照）之前。
8. 同一提交里更新本文与 `AGENTS.md` §8.2 对照表要求的各处。

**关键坑**：

- 描述以 JSON 为真相源，Rust 里的 `description` 只是占位（例外：`load_skill` 的描述是运行时拼的动态目录）。
- 权限只由 `.writes()` / `.presentation()` 决定，JSON 的 permission 字段不生效。
- 懒加载 stub 会以“一句话摘要 + 宽松参数壳”常驻；完整 schema 通过 `load_tools` 返回，不要为了显示完整参数把工具设成 always_loaded（会破坏前缀缓存）。
- **编辑/读取类能力优先并入 `edit` / `read` 的命名空间**（裸路径=文件系统、`artifact:`=Artifact 库、`kb:`=知识库），别为一个新存储再开一套读写工具——`write_file`/`edit_string`/`read_artifact` 那批工具就是这么被清掉的。

## 3. 新增一个用户技能

直接看 `src/skills/skill-creator.md`。核心规范：

- frontmatter 必须有 `name`（小写 ASCII/数字/连字符）和 `description`（触发条件写清楚）。
- `allowed-tools` 只是兼容性元数据，**不授权限**。
- 使用 `manage_skill`（action=create/update）生成草稿，用 `edit` 写文件，最后 `manage_skill`（action=publish）原子发布。
- 脚本是资源，发布 skill 不会自动把脚本注册为工具。

### 内置技能（编译进二进制）

1. 把 Markdown 放进 `src/skills/`（平台级）或 `src/skills/personas/default/`（顾清影 配件）。
2. 在 `src/skills/mod.rs` 的 `BUILTIN_SKILLS` 加一行 `(名字, include_str!(...), 平台级?)`。平台级 `true` = 任何人格都开着且不能关（当前有 skill-creator、script-creator、gqy-cli、webui-theme）；`false` = 可选件，默认人格全开，自定义人格要在人格清单 `plugins.skills` 里点名（当前只有 linux-game-compatibility）。
3. 目录里的同名技能会遮蔽内置技能。改完要重新编译。

## 3.5 新增内置脚本

1. 可执行文件放进 `src/scripts/personas/default/`，头部注释写契约：`# Description:`（英文，首句 ≤60 字符）、`# Parameters:`（JSON Schema）、可选 `# Id:`、`# Display name:`、`# Timeout:`、`# Group:`、`# Argv:`、`# Trust:`、`# Permission:`、`# Example:`、`# Hint:`、`# Requires:`。只在某个系统能跑的加 `# Platform: macos`（或 `linux`，可逗号分隔；`mac` / `darwin` / `osx` 都认作 macos），其他系统扫描时当它不存在。解析在 `src/tools/scripts/header.rs`，完整接口见 `docs/scripts/README.md`。
2. 打包时整个 `src/scripts` 拷到 `share/gqy/scripts`（`publish-release.yml` 与 `nix/package.nix` 已覆盖，不用改）。脚本新依赖的外部命令要按 `AGENTS.md` §7.3 两处同步。
3. 默认人格全挂；自定义人格只挂人格清单 `plugins.scripts` 里点了名的。

## 4. 新增通讯平台（PlatformDriver + PlatformAdapter）

平台层分三块：`platforms/common/` 是平台中立的回合机器（会话解析、限流、回合上下文与投递幂等闸、回合驱动、回复整形、平台指令与工具），`platforms/onebot/` 是 QQ，每个平台一个自己的目录。新平台照 `onebot/` 的样子：

1. 新建 `src/platforms/<name>/`，在 `platforms/mod.rs` 声明模块；平台标识（与会话绑定、`PlatformConversation::platform` 一致，QQ 是 `onebot`）加进 `src/platform_types.rs` 的 `PLATFORM_IDS`——「这个人格的全部平台会话」一类查询（重置人格、wipe、任务唤醒、目标驱动）靠它覆盖到新平台。
2. 实现 `PlatformDriver`（`platforms/driver.rs`）：`id`、`display_name`、`prepare`（按新配置准备连接，可能失败）→ 返回的 `PreparedPlatform::commit`（配置换上后生效）、`shutdown`。在 `PlatformRuntime::new` 的驱动列表里挂上；daemon 启动、`gqy reload`、WebUI 保存配置、退出都会遍历它（debug 构建会断言驱动 id 在 `PLATFORM_IDS` 里）。
3. 实现 `PlatformPolicy`（`platforms/policy.rs`）：插件开关、主人、静态私聊白名单、非管理员宿主工具、中间消息——回合里平台中立的代码只通过它问这些。在 `policy_for` 里加一个分支；QQ 的实现是 `platforms/onebot/policy.rs`（`impl PlatformPolicy for OneBotConfig`）。
4. 实现 `PlatformAdapter`（`src/platform_types.rs`）：必须实现 `send` 和 `bot_display_name`；按能力覆盖 `message_info`、`fetch_platform_file`、`group_members`、`set_group_ban`、`delete_message` 等，不覆盖的有明确的 not-supported 错误。
5. 把协议入站事件转成 `PlatformInboundEvent`（同在 `src/platform_types.rs`），填 platform/account/conversation/position/ingress_order/text/media。可信字段（发送者 id、是否管理员）由宿主算，不可信文本（昵称、正文）进提示词前过 `safe_prompt_field`（AGENTS.md §4.1）。
6. 用 `resolve_platform_session`（`platforms/common/scheduling.rs`）拿会话，再调 `run_platform_turn`（`platforms/common/turn_run.rs`）；排队/抢占用 `PlatformRuntime::acquire_session_turn/preempt_session_turns`（`platforms/mod.rs`）。
7. 出站消息用 `OutboundSegment::{Markdown,Text,Mention,ImageBytes,ImagePath,FilePath}` 和 `OutboundBody::{Segments,Forward}`，按你平台的能力序列化。投递经 `PlatformTurnContext::send`，§4.3 的两道幂等闸（图片 digest、文字 bigram）自动生效。
8. 新平台命令在 `platforms/common/commands.rs` 加描述符、解析与权限；新平台工具在 `platforms/common/tool.rs` 注册。
9. 配置：在 `config/platform.rs` 的 `PlatformsConfig` 加平台块（`platforms.qq` 不动）。

仍有少量 OneBot 特化：`common/access_control.rs` 用 onebot 平台名与 QQ 号、`common/file_reader.rs` 的 `platform_files/qq` 路径、主动发送与任务唤醒只走 `onebot/proactive.rs`。接第二个平台时一并参数化。iMessage 目前不是这里的平台，而是 `scripts/imessage/` 下的独立桥接；改成原生平台的方案稿在 `docs/design/2026-09-26-imessage-platform.md`（第一期「平台层整理」已完成，第二期起接 iMessage）。

## 5. 新增平台插件

插件 trait 在 `platforms/plugins/mod.rs` 的 `PlatformPlugin`：

```rust
impl PlatformPlugin for MyPlugin {
    fn descriptor(&self) -> PluginDescriptor {
        PluginDescriptor { id: "my_plugin", priority: 150, default_enabled: true }
    }
    // 服务哪些平台：缺省只服务 QQ（onebot）；空切片 = 所有平台。
    // 只有确认插件不依赖 OneBot 接口和 platforms.qq 时才放开。
    fn platforms(&self) -> &'static [&'static str] { &[] }
    // 按需覆盖 hook（返回 BoxFuture，项目不用 async-trait）：
    // observe_ingress / handle_command / register_tools / preempt_inbound
    // turn_started / observe_inbound / decide_trigger / before_turn
    // before_send / after_send / after_session_reset / after_persona_reset ...
}
```

然后在 `platforms/plugins/mod.rs` 的 `built_in()` 注册，插件 id 常量与设置结构放在 `config/platform_plugins/`（QQ 插件在 `qq.rs`），配置块是 `platforms.qq.plugins.<id>`；WebUI 设置卡片的字段在 `web/settings-schema/` 里加。

Hook 契约：

- `memory_content` 插件禁止改；`system_context` 必须字节稳定，动态内容走 `turn_system_context`。
- `before_send` 默认 `PreparedSend::unchanged`；改过 metadata 会自动补 fallback；转图/转发类插件应显式给 `fallback=原消息`。
- 固定输出可用 `send_fixed_tool_output` 旁路整个插件链，并压制后续模型回复。

## 9. 改 WebUI

- `web/` 下的文件由 `build.rs` 扫描后嵌入二进制，按「相对 `web/` 的路径」提供（`web/a/b.js` → `/a/b.js`）。加文件直接放进目录，不用改 Rust；`vendor/`、`index.html`、`fence-frame.html` 例外，见 `src/web/embedded.rs`。**改完必须重新 build**。
- 只改前端时不必每次重编：`GQY_WEB_DIR=$PWD/web cargo run --bin gqy -- web`（debug 构建），daemon 每次请求现读 `web/`，改完刷新浏览器即可。`/api/health` 的 `web_assets` 字段显示当前资源来源。发布构建忽略这个变量。
- 新文件在 `index.html` 里引用即可，`?v=构建号` 自动挂上。引用了却不存在的路径由 `index_references_resolve_to_embedded_assets` 测试拦下。
- 前端是分层 ES 模块：`core/` → `state/` → `widgets/` → `features/` → 入口 `app.js`，只能从左往右依赖；feature 之间互相引用要在 `test_scripts/web-deps.json` 写明理由，`test_scripts/web_dep_check.py` 在 CI 里查。根目录的 `settings.js`、`dash-*.js` 等是还没迁的旧脚本（`window.GqyXxx`）。设置页字段表在 `web/settings-schema/`，按文件名拼成 `/settings-schema.js`。
- 拆分与分层规则见 `docs/design/2026-09-24-webui-split.md`，目录说明见 `web/README.md`。
- 后端新路由：`src/web/server.rs` 的 `router`；读接口 `require_auth`，写接口 `require_mutation`。
- 新 SSE 事件：`RunEventMapper` 映射，事件必须带 run_id，否则被过滤。
- 样式在 `web/css/`，按文件名顺序拼成一份 `/styles.css`（顺序就是层叠顺序）。前端主题：在 `web/css/00-tokens.css` 加 `body[data-theme="..."]` MD3 token 块，并同步主题按钮。
- CSP 是 `script-src 'self'; style-src 'self'`，内联脚本/样式会被拦截。

## 10. 改渲染/回复处理

- 终端 Markdown 语法：`render_inline`、`render_line`；新工具摘要：`tool_subject`。
- 数学公式：`render/math/mod.rs` 的 `symbol_for`、`convert_command`、`unicode_math_lines`。

## 11. 数据库结构变更

1. 在 `state/migrations/mod.rs` 的 `MIGRATIONS` 末尾追加下一个版本（当前最新 v37，下一个 v38），并升 `LATEST_VERSION`。纯增量：不回填、不删列。
2. 轻量加列用 `add_column_if_missing`；重建表参考 v2。追加型数据用自增子表，别塞进 turns 的 JSON 数组列。
3. 新表加 CREATE + 索引，并在 `StateStore`/`ConversationDb` 加薄委托。
4. 改 `Turn` 字段：改 `state/conversation_db/rows.rs` 的 `TURN_COLUMNS` 与 `map_turn_row` 两处（按列名读取，不按位置）。
5. 迁移在 immediate 事务内跑并做 `pragma_foreign_key_check`。
