# 10 · 系统设计与架构

> ⚠️ **临时版本提示**：本文档由 DeepSeek 根据当前 顾清影 源码逐行整理，属于临时参考版本；正式版文档仍在施工中，内容可能与最新代码存在出入。请以 `gqy -h`、`gqy config`、仓库 README 及源码为准。

这一章给“想懂原理”的人：顾清影 由哪些部件组成、一次对话如何流动、为什么它能长期挂机还省钱。

## 2. daemon 与“远程优先”

- daemon 不是独立二进制：`gqy daemon start` 重新执行 `gqy __daemon`，入口 `daemon.rs` 再转发给 `web::run`（在 `web/mod.rs`）。
- 前端优先远程：聊天、reset、pop、models、tool-call 等操作先探测 IPC；daemon 活着就发命令，死了才本地直连兜底。
- 好处：REPL/WebUI 关掉，后台任务、QQ、Web 服务继续跑；重新打开前端能接回。
- IPC：Unix socket，4 字节长度 + JSON 帧，协议版本 3，最大帧 24 MiB。管理命令返回 `AdminResult`。
- 双核心保护：flock 锁保证同一套路径只有一个 daemon 或直连 core。

## 3. 一次对话的旅程（Normal 模式）

1. 用户输入 → 平台层（终端/Web/QQ）转成内部消息。
2. QQ 场景先过插件链：real_context 判断该不该回、message_history 记录、权限检查、群管理等。
3. `Agent::chat_stream_turn`：
   - 恢复僵尸回合、检查溢出。
   - 组装系统提示词、预设对白、历史、当前消息、运行时上下文、记忆联想、表情提醒。
   - 把“瞬态尾巴”写入 `turns.context_messages`（化石化）。
4. `chat_with_tools` 工具循环：
   - 取工具定义（stub/懒加载/全量）。
   - 调 `OpenAiCompatibleClient` 流式请求。
   - 解析 reasoning/正文/tool_calls。
   - 有工具就并行/串行执行，结果回填；最多 `max_tool_rounds` 轮。
5. 完成后：
   - 写 journal、completed、tool_flow、token 用量。
   - 记忆系统拿**用户原文**写短期日记。
   - 平台发送最终回复（QQ 可能转长图/合并转发）。
   - 启动缓存保温（若配置开启）。

## 4. 会话与消息如何持久化

- 数据库：`conversation.db`，SQLite WAL，迁移到 v37（`src/state/migrations/mod.rs` 的 `MIGRATIONS`）。新布局下每个账号一份，在 `home/<user>/conversation.db`（`StoreRegistry` 按身份路由）；没迁布局的老安装仍在 `state/` 下。
- 核心表：`sessions`、`turns`、`queued_prompts`、`turn_journal_events/segments`、`question_exchanges`、`user_attachments`、`artifact_assets`、`session_reviews`（聊后复盘）、redo 备份表、平台绑定表、授权表等。
- 每轮在数据库中是一条 `turns` 行；运行中状态 + journal 事件流保证崩溃后可重放“半成品”回复。
- 会话指针、平台绑定、人格隔离都靠 DB 唯一约束与事务。

## 5. 最重要的设计哲学：把上下文当成“只增的账本”

顾清影 长期挂着陪聊，上下文常常十万 token。大模型无状态，每一轮都要把全部历史重发一遍。于是**前缀缓存命中**成为省钱关键。

顾清影 的四条铁律：

1. **前缀即契约**：相同会话状态必须产生逐字节相同的请求前缀。时间戳、随机数、异步元数据要么不进前缀，要么进入后冻结。
2. **Append-only**：历史只能往后追加，禁止中间插入；已经注入的“瞬态内容”（时间、联想记忆、提醒）也写进历史原样回放，称为**化石化**。
3. **权限由代码承担**：提示词里的“你是管理员”不负责鉴权；发送者身份/权限在执行层拿真实 principal 判定。
4. **三份内容分离**：`raw_content`（用户原话，记忆只读它）、`display_content`（UI 显示）、`context_messages`（工程附加物）。缓存工程折腾字节不会污染记忆。

工具目录的三角困境：原生调用 / 前缀稳定 / 按需加载三者不可兼得。顾清影 选择 **stub 模式**——懒工具全部以“真名 + 首行摘要（描述第一行，≤60 字符）+ 宽松参数壳”常驻目录，tools 数组会话内字节恒定，完整 schema 用 `load_tools` 结果返回。实测工具循环缓存命中 95%–99.8%。

供应商差异策略：

- **普适层默认开**：字节纯度、append-only、化石化、stub 工具。
- **投放层默认关**：例如 keepalive 保温 ping——在 DeepSeek 官方上能把跨轮命中从 28% 拉到 94.9%，在按次计费网关上只会白烧请求额度。

每请求一行 cache log（`cache-usage.<date>.jsonl`）记录绝对 token 数：prompt / cache_read / cache_write / fresh。优化依据就是这行数字。

## 6. 溢出与压缩（compact/pop）

- 上下文到达窗口 `trim_at_ratio`（默认 80%）时开始处理。
- `on_overflow=compact`：先免费机械裁剪旧工具报告 → 仍超则 LLM 压缩：保留最新 2 轮，把旧轮折叠成摘要，并把 footprint（读/改/记忆）带进摘要；失败可重试/机械兜底。
- `on_overflow=pop`：把旧轮整体归档，从 DB 可恢复（终端 `/pop`，QQ 群默认 pop）。
- 压缩是唯一允许的“计划内冷启动”，要求单调：水位只前进、产物写入即承诺。
- 占用怎么量：有供应商实测锚点（上一回合最后一次请求的 prompt + completion）就用锚点，否则渲染整份请求用 o200k 估算（`agent/context_meter.rs`）。触发线和输入框的上下文圆环读的是同一个数。
- 分项（WebUI 点圆环看到的）只从真实请求的同一份字节里拆：消息走 `chat_messages`，工具走 `ToolRegistry::presented_definitions`（`definitions` / `stub_definitions` 也从它出），测试钉住「各分项之和 = 估算总数」（`agent/context_breakdown.rs`）。实测拆不开，与估算之差单列，不按比例摊进分项。接口 `GET /api/sessions/{id}/context/breakdown`，点开才算。

## 7. 并发与队列

- 一个会话同时只跑一个主回合；新消息在回合中自动排队（`queued_prompts`）。
- 排队插话会“超车”当前生成：generation 编号防止旧结果回写。
- QQ 平台全局最多 16 个运行中会话、64 个排队；默认每平台 running 8 / queued 16，可按会话/私聊/群聊覆盖。
- ask_question 每个工具批次最多 1 个、每回合最多 8 轮；不消耗工具轮。
- task 并行按 `subagent_concurrency`（默认 4）分批。

## 8. 渲染与前端

- 终端：流式 Markdown 渲染器（标题/表格/代码高亮/patch diff/公式半块或 Kitty 图形协议），ANSI 逃逸过滤，敏感 token 脱敏。
- 块级公式的行数随内容自然分配（与 Kitty 那条路同一套 retina 语义：RaTeX 以 2x 密度出图，显示尺寸取内容的一半），上限 8 行并按终端高度再收一道；表格单元格里的公式仍用固定行高。
- 非原生 Kitty 的终端把公式交给 `chafa`（`--probe-mode ctty` 经控制终端探测能力，所以捕获输出也不影响判断），Konsole/WezTerm/foot/iTerm2 之流因此能出真图；chafa 缺失或输出不是终端时才退回半块。
- QQ 长回复：reply_processor 插件可把超过阈值（默认 300 字符）的 Markdown 渲染成 PNG 图片，或转合并转发；由独立 renderer worker 进程（内存受限 512 MiB，1 小时空闲回收）完成，避免拖垮 daemon。
- WebUI：分层 ES 模块（`web/core`、`web/state`、`web/widgets`、`web/features`，入口 `app.js`）加根目录的老脚本；`build.rs` 扫描 `web/` 把静态资源编译进二进制，`web/css/` 各段拼成 `/styles.css`、`web/settings-schema/` 各段拼成 `/settings-schema.js`（规则在 `src/web/asset_rules.rs`）。SSE 事件 + HTTP API，ETag 用 build ID。debug 构建可设 `GQY_WEB_DIR=<仓库>/web` 让 daemon 现读目录。详见 `web/README.md`。

## 9. 一个值得知道的原则

> 缓存不懂语义，只懂字节。任何“看起来一样”的改动（时间戳、字段顺序、工具描述多一个空格）都可能让整段前缀缓存失效。改消息组装/工具目录/提示词时，先读这条。
