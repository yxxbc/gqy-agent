# 多方聊天室（WebUI）方案稿

> 状态：第一期（MVP）已施工（2026-09-27，WebUI）；随后补上「空房间增删发言人」与「跳过当前发言人」两项。前端样式在 `web/css/96-room.css`（发言人色块、谁在说话的状态行、建房对话框、侧栏建房键与会话列表的房间标记）；第二期（AI 之间 @ 接话、每位参与者的工具与记忆开关、中转映射表按最久未用淘汰）与第三期（TUI）未开工。
> 需求（用户，09-27）：开一个聊天室，勾选中转线的 CLI（Claude Code / Codex / Antigravity / Cline）和顾清影进来，大家在同一段对话里聊。先做 WebUI，TUI 之后再跟。

## 1. 现状与约束

调研结论（路径均为仓库相对路径）：

- 会话是单发言人模型。`Turn` 只有 `assistant_provider_id` / `assistant_model`，没有发言人字段（`src/state/conversation_db/types.rs:175-214`）。所有历史回复都以 `assistant` 角色回放，意思是「这是你说过的」（`src/agent/history.rs:185-285`）。
- CLI 中转续传靠前缀链：记录「发出的对话 + 本线自己的回复」的哈希，下一轮对上了就只发增量（`src/llm/openai_compatible/cli_relay/session.rs`、`mod.rs` 的 `ResumePlan`）。别人的回复以 `assistant` 插进来时预测失配，走整段重放；中转层也会把其他 assistant 一律渲染成 `Assistant:`，丢掉发言人身份（`cli_relay/payload.rs:240-274`）。
- WebUI 同一会话同时只允许一个回合（`src/runtime/run.rs:109-121`、`src/web/turns/mod.rs:333-361`）。不同会话可以并行。
- 多人发言已有成熟做法：QQ 群聊把他人发言按 `[时间] <发言人>: 内容` 渲染进用户消息，发言人和正文都过 `safe_prompt_field`；按水位线只带「上次回复之后」的新消息，旧轮逐字回放（`src/platforms/plugins/real_context/history.rs:165-330`、`inject.rs:689-889`）。可信身份走 `turn_system_context`，稳定策略走 `system_context`（`src/platforms/onebot/identity.rs`、`onebot/turn.rs:540-583`）。
- 平台侧已有一个 daemon 内的回合驱动：发 `StartTurn` 带 `TurnProfile`，订阅 `EventHub` 按 `run_id` 收集最终正文与 provider/model（`src/platforms/common/turn_run.rs:35-230`）。
- 前端头像与名字是全局单人格：`state.persona.name` + `makeAvatarFrame("her")`（`web/features/conversation/render.js:152-159`、`web/features/live/state.js:427-437`）。事件里没有发言人字段。

## 2. 方案：一个房间 + 每位参与者一个后台会话

```
            WebUI 聊天室（kind = room）
   ┌───────────────── room_messages（只追加）─────────────────┐
   │ #1 你：大家好                                             │
   │ #2 顾清影：……                                             │
   │ #3 Claude：……                                             │
   └──────────────────────────────────────────────────────────┘
        │ 轮到谁，就把「它上次发言之后」的新消息打包成一条用户消息
        ▼
   后台会话（kind = room-member，列表里隐藏），每位参与者一个
   ├─ 顾清影   → 普通供应商 + 她的人格
   ├─ Claude   → claude_code 中转线
   └─ Codex    → codex 中转线
```

- **房间记录是唯一真相**：新表 `room_messages` 按顺序只追加，存发言人、正文、run_id、状态。
- **每位参与者一个后台会话**：`sessions` 新增 kind `room-member`，`parent_session_id` 指向房间，`model_override` 钉死该参与者的 provider/model。它自己的回复在自己会话里是真正的 `assistant`，别人的话进用户消息。这样续传前缀天然只追加，中转线的 `ResumePlan` 每轮都能命中，只发增量。
- **打包格式**沿用 QQ 群聊：`[Room messages since your last reply]` 块，每行 `[HH:MM] <发言人>: 内容`，正文与名字过 `safe_prompt_field`；本参与者自己的历史发言不再重复。
- **身份与规则放 system 侧**（AGENTS §1.4、§4.2）：
  - 稳定部分进 `system_context`：房间规则、「你是谁」、成员名单（名单变动才变，属于计划内冷启动）。
  - 本轮可信信息进 `turn_system_context`：点名你的人、当前发言顺序。
  - 模型可见的机器文本一律英文短句（§1.5）。
- **参与者身份**：
  - 顾清影用她的人格，照常过人格提示词。
  - CLI 参与者以自身名义出场（Claude / Codex / Gemini / Cline），走一段短的英文「房间成员」系统提示词，经各线已有的 `--system-prompt` / `model_instructions_file` / agent.md / `-s` 注入。
- **发言驱动**：新增 `RoomDriver`，仿 `run_platform_turn`：对每位要发言的参与者，依次在其后台会话里跑一回合，流式事件转发到房间，完成后把正文追加进 `room_messages`。一轮内**顺序发言**，后发言的能看到前面的人刚说的话。好处：
  - 排序确定；
  - 不触碰「同会话并发」；
  - 也避开 agy 全局 `mcp_config.json` 后写者覆盖的问题。
- **前端事件**：`run.started` / `run.completed` 与增量事件带上 `room_id` + `participant_id`；新增 `room.message` / `room.participant_typing`。前端按参与者渲染名字、颜色和头像。

## 3. 发言规则（用户已定：轮流回）

- 你每发一条消息，所有参与者按房间里的排列顺序依次各回一次。后发言的人能看到前面的人刚说的话。
- 同一时间只有一位在说话。你在这一轮进行中又发了消息，会先排队，等这一轮说完再开下一轮。
- 任何时候可以停止：取消当前发言人，并清空这一轮剩下的队列。
- 也可以单独「跳过」当前发言人：只取消他这一轮，轮次继续、后面排着的轮不动，被跳过的那次回复不写进房间。
- 增删发言人只允许在房间空闲且还没有任何消息时（服务端同样校验）；已有成员的模型保持不变，要换模型就移除再加回来。
- 参与者顺序在建房时拖动调整，默认顾清影第一个。
- 第二期再考虑：参与者之间互相 @ 接话、「接着聊」按钮。

## 4. 数据（迁移只在 MIGRATIONS 末尾追加，纯增量）

- `sessions.kind` 新值：`room`（可见的房间）、`room-member`（隐藏的后台会话）。不加列。
- 新表 `room_participants`：`room_id, participant_id, label, color, provider_id, model, persona_scope, backing_session_id, sort, watermark_seq, tools, memory`。
- 新表 `room_messages`：自增 `id`，列为 `room_id, seq, speaker_kind (user|participant|notice), participant_id, content, run_id, status, created_at`。按 §3.2，追加型数据用子表，不塞进 JSON 列。

## 5. WebUI

- 会话侧栏：聊天室和普通会话混排，带群组图标；新建菜单里加「新建聊天室」。
- 建房对话框：名字，参与者清单（已启用的中转线 + 顾清影 + 可选其他模型，每位可改模型），可拖动排发言顺序。
- 房间视图：每条消息显示发言人名字、颜色点和头像；多人同时在队列时显示「谁在输入」；输入框支持 `@` 补全；有「接着聊」和「停止」按钮。
- 复用 `createAssistantMessage` / `ensureLiveArticle`，把写死的 `state.persona.name` 和 `"her"` 改成参数。
- 新目录 `web/features/room/`，跨 feature 依赖登记到 `test_scripts/web-deps.json`，新事件名加到 `web/core/constants.js` 的 `EVENT_NAMES`。

## 6. 已知风险

| 风险 | 处理 |
|---|---|
| 中转会话映射表上限 128，满了整表清空（`cli_relay/session.rs:59,339`） | 房间参与者多时更容易撞上。改为按最久未用淘汰 |
| agy 与 codex 的指令文件超过 1 小时未改会被清理，可能删掉正在用的那份（`antigravity/setup.rs:90-111`） | 用之前 touch 一下，或改成按引用计数清理 |
| 工具桥只认 gqy 会话 id，不认参与者（`src/cli/mcp_serve.rs`） | 后台会话一人一个，天然隔离 |
| CLI 参与者原生工具默认 `all`，在聊天室里会直接跑 Bash、改文件 | 房间内默认关工具（见 §8） |
| 中转线成本多半算不出价格（models.dev 查不到别名） | 只显示 token，不显示金额 |
| claude / cline 的提示词走命令行参数，单参数上限 128 KiB | 房间提示词很短；打包的新消息沿用 cline 的 96 KiB 预算，从最老的丢起 |
