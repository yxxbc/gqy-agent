# TUI 验收问题清单（2026-09-24）

用户手测 09-24 这一批 TUI（`49e55909`…`e15dc60d`，本机无语音 release 版）时报的问题。每条是「现象 / 复现 / 初步判断」，初步判断只是施工前的猜测，动手前先复现、找根因（AGENTS §5.1）。

## 1. 空会话里 `/goal`，底栏左右闪跳

- **现象**：打开 `gqy` 什么都没聊，直接输 `/goal …`，输入框下面那一行（底栏：模式、模型、上下文）左右来回跳。
- **复现**：`gqy` → `/goal 随便一个目标`。
- **初步判断**：空会话时输入框在大厅的窄框里（`layout_box`），goal 开始后布局可能在「大厅窄框」和「屏底全宽」之间来回切，底栏的左边距跟着变。

## 2. `/goal` 的输出不留在 TUI 历史里

- **现象**：goal 跑完，正文区没有留下任何东西，像是没有输出。
- **复现**：同上，等 goal 跑出结果。
- **初步判断**：输出可能是直接 `println!` 出去的，没进全屏缓冲，下一帧重画就被抹掉了。`/help` 以前是同一个问题，改法是走 `repl_note`（见 `commands.rs::repl_help_text` 的注释）。

## 3. `/usage` 直接打印在正文里，建议做成浮窗

- **现象**：用量表整块印进对话正文，把对话冲散。
- **建议**：做成浮层（和子代理面板、命令候选一类），Esc 关闭，不进正文。

## 4. `/config` 还是旧界面，分组藏得太深

- **现象**：
  - 设置界面还是旧的菜单风格，和新的 TUI 视觉（圆角框、主色）不一致。
  - `/config <分组>` 能直达的六个分组，在完整菜单里藏在「全局参数设置」下面一层，用户不知道有这些，要靠记。
- **建议**：完整菜单顶层直接列出各分组，名字和 `/config <分组>` 一致；视觉跟上新 TUI。视觉改造的范围需要先和用户确认。

## 5. 行内代码（`code`）没有渲染

- **现象**：回复里的 `` `code` `` 原样显示反引号，没有上色。
- **初步判断**：样式表里有 `INLINE_CODE_STYLE`，查一下全屏正文的 markdown 路径为什么没用上。

## 6. 欢迎框的「最近」改成碎碎念

- **现象/诉求**：欢迎框右侧目前列最近 3 个会话，用户想换成顾清影的「碎碎念」：预设几句，随机挑一句显示。
- **待定**：预设几句、谁来写文案（用户写还是我写了给用户挑）、是否跟人格走（换人格后碎碎念也换）。

## 7. 没聊天时底栏就显示上下文占用 7.3k

- **现象**：直接 `gqy` 进去，一句话没说，底栏已经显示上下文 7.3k。
- **初步判断**：这是按系统提示词 + 工具目录估的前缀大小，技术上是真的会占，但对用户来说像是「还没聊就用掉了」。
- **待定**：空会话时隐藏上下文，还是标注成「基础占用」。

## 8. 吉祥物设成黑猫后不显示

- **现象**：`display.mascot` 改成 `cat` 后，欢迎框里没有猫。
- **初步判断**：黑猫是 48 列 × 23 行，欢迎框给吉祥物的地方放不下时 `Mascot::render` 返回 `None`，只画文字，没有降级方案。需要确认用户的终端尺寸，并给黑猫做一个小尺寸版本或按比例缩放。

## 9. 文件类工具的输出，鼠标点击没反应

- **现象**：读文件、写文件这类工具的时间线条目，点了不展开。
- **初步判断**：这些工具的输出可能没登记成可展开块（`render::blocks::register`），或登记了但内容为空。

## 10. 输入框自动换行后点击文字，光标乱跳、底栏变两行

- **现象**：输入框里的文字自动换行后，鼠标点在文字上想移动光标：光标先跳到点击的位置，又跳回句尾；同时底栏（开发模式、模型那一行）变成两行。
- **初步判断**：点击定位按未换行的列算，或者点击后的重画用了错误的行数，把底栏多画了一遍。09-23 改圆角输入框时动过装饰宽度（`INPUT_BOX_TEXT_INDENT`、`decoration_width`），嫌疑最大。
